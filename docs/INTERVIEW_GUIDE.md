# AlphaLens 面试讲解提纲

## 一句话介绍

我做了一个 React + FastAPI + PostgreSQL 的可部署应用。它是一个 A 股投研平台，包含市场概览、因子选股、AI 投研、资金监控、个股对比、AI 每日复盘、行业轮动和系统设置八个模块。

## 项目架构

```text
React + TypeScript
        ↓ REST API
FastAPI
 ├─ PostgreSQL：保存业务快照、研报和异步任务
 ├─ 公开行情 Provider：手动刷新市场数据
 └─ OpenAI-compatible LLM：生成研报和每日复盘
```

- 前端使用 React、TypeScript、React Router 和 Recharts，实现页面路由、数据展示与图表交互。
- 后端使用 FastAPI、Pydantic、SQLAlchemy 和 Alembic，按 Route → Service → Repository 分层。
- PostgreSQL 统一保存因子结果、市场快照、行业轮动、研究报告和任务状态。
- Docker Compose 编排 PostgreSQL、后端和 Nginx 前端，支持一条命令启动。

## 核心业务流程

1. 平台读取因子快照，展示 TOP30 股票、因子权重和验证指标；用户可刷新当前候选池的市场敏感因子并重新排名。
2. 用户可以筛选股票，并比较 2–5 只股票的综合得分和五类因子贡献。
3. 市场、资金和行业页面支持手动刷新，并记录数据来源、行情时间和抓取时间。
4. 公开数据源不可用时，系统继续展示最后一次成功快照并提示数据可能陈旧。
5. 配置 LLM 密钥后，用户可以异步生成个股研报和每日复盘，并通过任务接口轮询状态。
6. 未配置密钥时，AI 页面仍可访问，但生成按钮禁用并提示“需配置密钥后才能生成”。

## 面试时重点讲的三个设计

### 1. 快照与失败回退

外部行情接口可能超时或限流，所以刷新成功后才更新 PostgreSQL。刷新失败时保留已有数据，避免整个页面不可用。

因子刷新会并发获取候选股日线，先寻找所有股票的最新共同交易日，再更新 20 日动量、换手率变化和 60 日波动率。财务指标沿用最近披露值，页面不会把它们标记为盘中实时数据。

### 2. 通用异步任务

个股研报和每日复盘共用一套任务模型，通过 `kind` 区分任务类型。前端使用任务 ID 轮询状态，避免 HTTP 请求一直等待模型返回。

### 3. 密钥与数据边界

LLM 密钥只通过服务端环境变量配置，前端只能读取“是否已配置”，不能读取密钥。平台不会在无密钥时用固定模板伪造 AI 内容。

## 三分钟讲解示例

“我做了一个 React + FastAPI + PostgreSQL 的可部署应用，产品定位是个人 A 股投研平台。前端有八个业务页面，后端提供 REST API，并按 Route、Service、Repository 分层。PostgreSQL 保存因子、行情快照、研报和任务状态。

这个项目主要解决了两个工程问题。第一个是公开行情接口不稳定，所以我设计了持久化快照和失败回退机制：只有刷新成功才覆盖数据，失败时继续展示最近一次快照，并在页面标明来源和新鲜度。第二个是 LLM 调用耗时较长，所以研报和每日复盘采用通用异步任务，前端通过任务 ID 轮询结果。

部署方面，我用 Docker Compose 启动 PostgreSQL、FastAPI 和 Nginx 前端。没有配置模型密钥时，AI 页面仍然可以展示历史内容，但生成按钮会禁用，避免产生虚假结果。这个项目不包含真实交易、用户权限和逐笔实时行情，定位是一个可以完整演示数据流、服务分层和部署流程的个人全栈项目。”

## 项目局限性

- 不包含真实交易、多用户权限和逐笔实时行情。
- 公开行情存在供应商延迟或接口变更风险。
- LLM 输出受输入数据和模型能力限制，不构成投资建议。
- 当前后台任务适合个人展示；高并发生产环境应使用独立任务队列。
